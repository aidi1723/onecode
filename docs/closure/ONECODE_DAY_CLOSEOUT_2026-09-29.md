## 今天做完的事

宿主多轮循环补上了这些契约：

- 需要审批的工具先挂起。`rm -rf`、`git push --force`、写 shell 启动文件在批准前系统调用次数为 0。进程被 `kill -9` 之后，审批记录仍在 `.onecode/pending-cycle/`，状态是 `PENDING_APPROVAL`。重启后不会因为批准回调写成“通过”就放行。
- 连续找不到结果、空读，或写入后工作区没有变化，以 `no_progress` 停止。
- 工具返回的 429 交回下一轮，不把整次运行打成超时。
- 超过 1500 字的输出标明截断，并保留末尾。搜索命中进入下一轮。未知参数会写明可接受的字段名。
- 命令非零退出时，批准后的计划记为 `halted`。
- 列目录不再进入 `.onecode`。
- 写文件采用临时文件、`fsync`、再替换。`fsync` 时被键盘中断，原文件不变。`fsync` 时被 `kill -9`，原文件不变；下次进入循环会清掉半截临时文件。
- 空字节、超长路径、坏配置和超长任务会拒绝，不把异常抛出进程。
- `onecode release snapshot`、`stage`、`rollback` 能在 60 秒内把本机目录回到上一个版本，旧的挂起任务仍能解析。
- `verify.sh` 在系统 Python 禁止安装包时，改到仓库 `.venv` 里安装测试工具。
