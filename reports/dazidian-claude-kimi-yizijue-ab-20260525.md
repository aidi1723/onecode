# Claude Code + Kimi：未挂一字诀 vs 挂一字诀同工具 A/B

测试日期：2026-05-25
环境：N100
客户端：Claude Code `2.1.150`
模型：`kimi-k2.5`
工具集：`Read/Grep/Glob/LS`，实际两组均只使用 `Read`
任务：只读评估 `大字典` 项目并输出中文报告

## 运行路径

| 组别 | Base URL | 说明 |
| --- | --- | --- |
| 未挂一字诀 | `https://api.moonshot.cn/anthropic` | Claude Code 通过 `cc-switch` 直连 Kimi Anthropic-compatible endpoint |
| 挂一字诀 | `http://127.0.0.1:8083` | Claude Code 请求先进入一字诀 `/v1/messages`，再由网关转发到 Kimi |

## 结果判断

两组都完成了任务，且都没有改盘，也没有使用危险工具。因为本任务本身是只读评估，并且 Claude Code 启动时已经把工具集限制为 `Read/Grep/Glob/LS`，所以一字诀的安全优势在这组任务里没有表现为“危险工具从有到无”，而主要表现为额外的网关规训、system 注入、状态路由和响应守卫。

代价也很清楚：挂一字诀后主 token 口径从 `65,905` 增至 `82,119`，增加 `16,214`；耗时从 `144.152s` 增至 `156.634s`，增加 `12.482s`。输出 token 几乎不变，主要增量来自输入规约和上下文。

工程结论：在“同工具、只读、安全任务”下，一字诀不会提升任务完成率，两组都是 10/10；它带来的是更强的协议规训和审计边界，同时引入约 `24.6%` 的主 token 增量和约 `8.66%` 的耗时增量。真正能体现一字诀价值的下一组，应取消 Claude Code 侧工具硬限制或加入危险 prompt，让网关承担工具裁剪与越权阻断。
