# OneCode Maintenance Log

Date: 2026-07-04
Maintainer: Codex session
Scope: Release readiness, packaging, CI, and source quality gates

## Session Goal

Continue the project review follow-up by closing release packaging gaps,
expanding CI coverage, recording design-source scope, and adding a lightweight
source quality gate without introducing runtime third-party dependencies.

## Change Record

### Packaging and CI

- Added `onecode.tui` package data so `styles.tcss` is included in wheels.
- Added `scripts/check_wheel_assets.py` to verify required wheel assets by
  inspecting built wheel contents.
- Expanded GitHub Actions verification to Python 3.11, 3.12, and 3.13.
- Added a CI wheel build and packaged-asset check after the normal verification
  script.

### Design Contract

- Expanded `DESIGN.md` scope from `src/onecode/tui` to both
  `src/onecode/tui` and `src/onecode/web`.
- Recorded that the local Web Gateway should keep the same dark terminal
  palette, compact operator-console density, and restrained surface treatment
  as the Textual TUI.

### Source Quality

- Added `scripts/check_source_quality.py`, a stdlib-only AST gate for oversized
  functions and classes.
- Preserved existing large hotspots through an explicit allowlist rather than
  mixing behavior-preserving quality gates with a broad decomposition refactor.
- Wired the gate into both `scripts/verify-core.sh` and `scripts/verify.sh`.

### Release Audit

- Upgraded `scripts/release-audit.sh` from passive diff/untracked listings into
  a local readiness checklist.
- The script now runs `git diff --check`, source quality, a temporary wheel
  build, and packaged-asset validation.
- The script explicitly records `publish action: not performed`.
- Temporary `build/` output from the wheel build is cleaned before release
  candidate listing when it was generated by the audit run.
- Temporary wheel build directories created by release audit are also cleaned
  before release candidate listing and on script exit.
- Added a behavior-level release-audit regression test using a fake Python
  backend so generated audit artifacts can be tested without network access.

### Closure and Online Update Preparation

- Added `docs/ONECODE_RELEASE_READINESS_CLOSURE_2026-07-04.md` as the
  stage-level closure and handoff record.
- Updated `docs/RELEASE_CHECKLIST.md` with the 2026-07-04 release readiness
  pass status and non-applicable UI rebuild/browser-smoke notes.
- Prepared the branch for commit and push to `origin`.

### CLI Service Decoupling Phase

- Added `docs/superpowers/specs/2026-07-04-onecode-cli-service-decoupling-design.md`
  to define the next maintenance phase boundary.
- Added `docs/superpowers/plans/2026-07-04-onecode-cli-service-decoupling.md`
  with the TDD extraction plan.
- Added `src/onecode/kernel/diagnostics.py` for shared doctor checks.
- Added `src/onecode/kernel/run_inspection.py` for shared run inspection,
  list-runs, delivery summary, verifier evidence, task-resume evidence, and
  WAL-backed inspection helpers.
- Kept compatibility exports in `onecode.cli` for existing CLI/tests/downstream
  imports.
- Updated Web API and TUI workers to import shared services from kernel modules
  instead of `onecode.cli`.
- Added import-boundary and compatibility-export tests.
- Moved the `inspect_run` source-quality allowlist entry from CLI to the new
  run-inspection module.
